# Amai 产品定义

> 状态：草案（2026-10-19）。本文档描述产品定位、目标用户、需求与 MVP 范围。架构见 [architecture.md](architecture.md)，记忆系统见 [memory.md](memory.md)，开发计划见 [roadmap.md](roadmap.md)。

## 1. 一句话定位

Amai 是一个运行在 macOS 上的 **Ambient Personal AI**：在后台持续感知用户在电脑上的活动，自动把这些活动理解为语义化的上下文，并沉淀为用户可读、可编辑的 Markdown 长期记忆。

与传统助手的区别在于：**用户不需要主动告诉它自己在做什么**。

### 市场位置（2026-10-19，详见 [references/competitors.md](references/competitors.md)）

- Rewind 已于 2025-12 随 Limitless 被 Meta 收购而关停；Screenpipe 转向企业工作流并改为 source-available；Dayflow 只做工作日志；Ambi 刚公测，以云端语音为核心，屏幕感知与长期记忆停留在宣称层面。
- macOS 上目前没有在售的"本地优先 + 多模态 + 用户可读可编辑的长期记忆"消费产品。这是 Amai 的空位。
- Amai 不与 Ambi 争"主动 Agent"叙事，先把感知 → 抽取 → 记忆的基础做可靠。

## 2. 目标用户（MVP 阶段）

- 单一用户，macOS（Apple Silicon）作为主力工作机。
- 长时间在电脑上进行知识工作：研究、写作、编程、阅读、会议。
- 希望拥有"自己的数据自己掌握"的个人记忆系统，而不是把生活数据交给云端。
- 能接受在 Markdown 文件层面直接查看和修改记忆。

MVP 阶段的首要用户是项目作者本人，产品决策以"作者每天愿意开着它"为验收标准。

## 3. 核心用户价值

| 价值 | 说明 | 对应能力 |
|---|---|---|
| 自动回顾 | "我今天 / 这周做了什么" 无需手动记录 | daily 记忆、活动时间线 |
| 上下文记忆 | 记住正在推进的研究、项目、决策和它们的变化 | work/、goals/ 专题记忆 |
| 长期画像 | 系统逐步形成对用户偏好、习惯、目标的稳定理解 | summary.md |
| 隐私可控 | 数据本地处理，用户随时暂停、检查、删除 | 采集控制、检查器、删除机制 |
| 为未来 Agent 打基础 | 记忆是未来主动式助手的"地基"，不是终点 | 可检索的记忆接口 |

## 4. 产品原则（来自 AGENTS.md，产品视角的解读）

1. **Ambient by Default**：默认不打扰。没有必填的输入框，没有每日提醒去"记日记"。
2. **Privacy First**：默认一切本地。任何外部传输必须是用户显式开启的、可见的、可关闭的。
3. **Markdown-based Memory**：记忆对用户完全透明。用户用任何编辑器打开记忆目录都能看懂。
4. **可信而非全知**：系统区分"看到的事实"和"推断的结论"，不把猜测当事实写进记忆。
5. **低存在感、低消耗**：长时间后台运行不应让用户感知到风扇、卡顿或电池明显下降。

## 5. 功能需求

### 5.1 感知（MVP 必须）

- 屏幕内容采集：自适应采样，画面不变时降低频率。
- 键鼠活动采集：记录**活动强度和焦点切换**（应用、窗口标题、输入节奏），**不记录按键内容**。
- 系统音频与麦克风采集：MVP 后期加入，初期可关闭。
- 用户可随时开启 / 暂停 / 停止采集，菜单栏显示当前状态。
- 对敏感场景自动暂停或跳过：安全输入模式（密码框）、用户设置的排除应用 / 网站列表。

### 5.2 抽取（MVP 必须）

- 屏幕 OCR 与应用上下文提取。
- 将一段时间内（例如 10–20 分钟）的感知数据整理为"活动片段"：做了什么、用了什么、属于哪类活动。
- 支持本地模型（优先）与外部模型（需显式开启）。
- 输出带时间范围、来源和置信度；区分观察与推断。

### 5.3 记忆（MVP 必须）

- 按 [memory.md](memory.md) 定义的目录结构写入 Markdown。
- 每日自动生成 daily 记录。
- 专题记忆（work、goals 等）按写入规则更新，不无条件写入。
- summary.md 通过整理机制定期更新。
- 提供基于问题的记忆检索接口（先服务于内部整理与未来对话，MVP 可以只有命令行 / 开发接口）。

### 5.4 用户界面（MVP 最小）

- 菜单栏常驻：状态、开关、暂停、打开记忆目录、打开设置。
- 设置：采集模态开关、排除列表、模型 Provider 配置、存储位置、保留期限。
- 检查器（最小版）：查看最近的活动片段及其来源，支持删除。

### 5.5 明确不做（MVP）

- 对话式问答界面（可在记忆层稳定后作为下一阶段）。
- 主动提醒、自动执行任务等 Agent 行为。
- 跨设备同步、移动端、Windows。
- 多用户、团队协作。
- 永久保存原始截图 / 录音作为"回放"功能（这是 Rewind 式产品的路线，不是 Amai 的）。

## 6. 非功能需求

| 维度 | 目标（MVP，待测量校准） |
|---|---|
| CPU | 空闲时接近 0，采集时平均 < 5% 单核 |
| 内存 | 常驻 < 300 MB（不含模型推理时的临时峰值） |
| 电池 | 用户主观感知不到明显差异；提供"低功耗模式" |
| 磁盘 | 原始数据有 TTL，默认 24–72 小时自动清理；记忆文件增长可预期 |
| 稳定性 | 可连续运行数天；崩溃或权限变化后能自动恢复 |
| 延迟 | 活动片段在时间窗口结束后数分钟内生成即可，不要求实时 |

具体数值以实际测量为准，不作为硬性承诺。

竞品教训（Rewind 用户报告磁盘 6–14 GB/月、电池每小时掉 10%；Screenpipe 用户报告 CPU 超 100%、内存超 10 GB）表明资源成本是第一流失原因。因此额外要求：

- 按电源与热状态节流：电池供电时降低采集与推理频率，重计算优先在插电时执行。
- 存储占用与保留期在 UI 中可见、可调；不能让用户事后发现磁盘被占满。
- 在文档中公布实测的 CPU / 内存 / 磁盘 / 电池数据，而不是宣传口径。

## 7. 隐私需求（产品层）

- 首次启动明确说明采集内容、存储位置、外部传输策略。
- 采集状态始终可见（菜单栏图标变化）。
- 排除列表：应用、浏览器域名（后期）、时间段。
- 安全输入检测：密码输入期间不采集键鼠，并跳过对应时段的屏幕内容。
- 原始数据（截图、音频）默认短期缓存，处理后删除。
- 用户可删除任意时间段的全部派生数据。
- 外部模型调用默认关闭；开启时明确展示哪些数据会被发送。
- 麦克风与系统音频分开控制；麦克风（线下对话）采集默认关闭。旁观者告知是所有语音产品共同的法律与伦理争议点，Amai 不默认开启。
- 提供一处"数据去了哪里"视图：本地有什么、什么被发到外部、何时删除。
- 本地存储加密与系统身份验证绑定列为后续评估项：Microsoft Recall 的经验表明"完全本地"不等于用户信任（MVP 先依赖 FileVault 与用户目录权限）。
- 本地优先与 Markdown 记忆作为**长期承诺**写入文档。Screenpipe 的许可突变与 Rewind 的转云都直接损害了社区信任。

## 8. 成功标准（MVP）

- 作者连续使用 2 周以上，每天查看 daily 记录并认为"基本准确、有用"。
- 系统资源占用在第 6 节目标范围内。
- 没有发生一次"敏感信息被写入记忆或日志"的事故。
- summary.md 在两周后能反映出作者的主要项目、习惯与目标，且作者愿意保留它。

## 9. 待讨论的产品问题

- 记忆目录放在哪里（`~/Amai/memory` 这类用户可见目录，还是 Application Support）？倾向前者，以体现"用户可直接编辑"。
- 活动片段的时间窗口长度（10 / 15 / 30 分钟）及是否按应用切换自适应。
- 对话问答界面是否作为 MVP 之后的第一个功能。
