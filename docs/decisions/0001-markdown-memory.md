# 0001 · 以 Markdown 文件作为长期记忆的主要存储

- 状态：Accepted（由 AGENTS.md 确认，此处作为正式记录）
- 日期：2026-10-19

## 背景

Amai 需要一个可持续更新、可检索、可由用户直接阅读和修改的长期记忆系统。候选方案包括关系型 / 文档数据库、向量数据库、以及纯文本文件。

## 决策

长期记忆以 **Markdown 文件** 为主要持久化格式和唯一真相来源，按 [memory.md](../memory.md) 的目录结构组织。允许使用额外的索引、元数据或缓存提升检索性能，但它们都是派生物，必须可以从 Markdown 完整重建。

这是项目的长期技术方向，不是 MVP 的临时方案。

## 备选方案

| 方案 | 未采用原因 |
|---|---|
| SQLite / 文档数据库作为主存储 | 用户无法直接阅读、编辑；与"记忆属于用户"的产品原则冲突 |
| 向量数据库作为主存储 | 不可读、不可审计；embedding 模型更换即失效 |
| Markdown + 数据库双主存储 | 两个真相来源必然漂移；维护成本高 |

## 取舍与风险

- 检索性能依赖派生索引；索引与文件的同步是实现复杂度所在。
- 结构化字段（金额、日期）在 Markdown 中的机器可读性弱于数据库；通过约定的条目格式与来源标记缓解。
- 大量文件的并发写入需要谨慎；MVP 为单进程单写者。

## 影响

- 记忆层接口围绕"文件 + section"设计。
- 所有索引放在应用内部目录，与记忆目录分离。
- 用户外部编辑必须被尊重，系统不得覆盖。
