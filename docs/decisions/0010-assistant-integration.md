# 0010 · 内置助手（Eira 集成）：统一感知、独立的模型运行时与 Agent

- 状态：**Accepted**（2026-11-18 用户确定方向与范围并要求实现）。其中"Agent 循环 + 记忆工具"的部分由 ADR-0011 取代：普通问答改为后端检索记忆、不经过工具调用；下文「Agent 上下文的排列」中关于工具与 `look_at_screen` 的描述以 0011 为准。扩大了 ADR-0004 中"云端只用于记忆整理"的边界：助手的 Agent 模型与辅助视觉模型也可以选用云端来源。抽取层始终本地不变。辅助视觉模型已于 2026-11-18 移除：Claude 订阅改用 stream-json 后所有来源都能直接看截图，下文提到它的地方不再适用。
- 日期：2026-11-18

## 背景

Amai 此前只有"感知 → 抽取 → 记忆"的后台流水线和只读的记忆浏览。用户另有一个独立应用 Eira（按快捷键唤起、能看当前屏幕的本地对话助手）。把两者合在一起，助手就既能看到"现在屏幕上是什么"，又能查到"过去做过什么"。

用户确定的要求：

1. 后台采集与交互式读取共用同一套截图、OCR、辅助功能读取和隐私策略；不改变后台截图频率与 15 分钟抽取流水线。
2. 模型运行时从抽取层解耦，支持本地 MLX 与多种云端来源；Agent、抽取、辅助视觉模型各自配置，Agent 不设默认模型，相同的本地模型共享权重。
3. Agent 支持流式对话、多轮历史、KV cache、工具调用；记忆通过已有的 `search_memory` / `get_timeline` / `get_memory` 读取。
4. 迁移 Eira 的聊天界面与快捷键，并加入对选中文字的快速操作（翻译、润色、解释、Ask Amai）与安全的文本替换。
5. 交互式推理优先于后台任务。
6. 暂不做：浏览器 DOM 读取、主动 Agent、记忆写入、P2P、iOS。

## 决策

### 模块

```text
AmaiCore ← AmaiInference ← AmaiExtraction
AmaiCore ← AmaiCloud
AmaiCore、AmaiMemory ← AmaiAssistant
以上全部 ← Amai（App：面板、快捷键、设置、装配）
```

- **AmaiCore** 新增三组契约：`ChatModel`（统一的对话接口）、`LiveContextReading`（交互式屏幕读取）、`TextRecognizer`（OCR，从抽取层移来）。
- **AmaiInference**（新）：本地 MLX 模型的加载、共享与调度。`ModelProvider`、模型目录与下载从抽取层搬到这里；抽取层重新导出它，使用抽取层的代码不变。
- **AmaiAssistant**（新，不含界面）：Agent 循环、每轮上下文的组装、记忆与屏幕工具、会话存储、快速文本操作。只依赖契约与记忆层的只读 `MemoryAPI`。
- 感知层新增交互式读取；OCR 的 Vision 实现移到感知层，后台抽取由 App 注入同一个识别器。

### 统一的对话接口

`ChatModel.stream(ChatRequest) -> AsyncThrowingStream<ChatEvent>`。请求无状态：每次给出完整的 system、工具定义与消息列表；事件为文本增量、工具调用、结束（含用量）。

| 实现 | 流式 | 工具 | 图片 | 说明 |
|---|---|---|---|---|
| 本地 MLX（`MLXChatModel`） | ✓ | ✓ | ✓ | 跨轮复用 KV cache |
| Anthropic API Key | ✓ | ✓ | ✓ | 请求顶层 `cache_control` 自动缓存；思考块原样带回 |
| OpenAI 兼容接口（API Key，可改接口地址） | ✓ | ✓ | ✓ | 接入其他云端服务的通用途径 |
| ChatGPT 订阅（Responses API） | ✓ | ✓ | ✓ | |
| Claude 订阅（本机 Claude Code） | ✓ | ✗ | ✓ | `claude -p` 的 stream-json 输入输出（2026-11-18 起；此前为整段返回、不传图）。CLI 对输入里的每条用户消息各回答一次，历史不能作为多条消息回放，仍拼成文字稿放进一条消息 |

云端来源、API Key 与登录状态沿用记忆整理的配置与钥匙串条目，不另建一套账户。

### 本地运行时

- `LocalModelRuntime` 按模型标签登记唯一的 `LocalModelHost`：抽取、整理、Agent、辅助视觉模型选了同一个本地模型时只加载一份权重。
- `InferenceGate`：全局串行闸门，等待者按优先级出队（交互式先于后台），不抢占进行中的生成。后台任务（抽取、整理）在开始一批工作前检查"最近 30 秒是否有交互式请求"，有则整批推迟。
- 交互式请求要加载的模型与已加载的其他模型合计超过本机内存六成时，先卸载其他模型。
- 对话的 KV cache（移植自 Eira）：保留一个会话，记录已进入缓存的消息指纹；新请求的消息列表以它为前缀时只处理新增部分，否则重建。取消、出错、换模型、空闲卸载、内存压力都会作废缓存。快速操作标记为一次性请求，不读写会话缓存。

### Agent 上下文的排列

固定的 system 与工具定义 → 只追加的历史 → 本轮的实时上下文与问题 → 按需的工具结果。

- system 里没有任何会变的内容；时间、应用、选区、屏幕文字都在本轮 user 消息开头的 `<context>` 块里，发出后成为历史、不再改写。
- 屏幕文字与上一轮基本相同时不重复带；最近状态只带上一轮之后新出现的；截图不留在历史里。
- 截图按需提供：模型调用 `look_at_screen`，或用户对某条消息打开"带上屏幕"。纯文本 Agent 由辅助视觉模型把截图描述成文字。
- 回答下方的记忆来源由工具调用的实际结果记录，不依赖模型自己引用。

### 感知层的交互式读取

- 采集器每次截图后把画面留在内存（每块显示器一帧）。交互式读取在画面还新鲜（默认 2 秒）且前台应用没变时复用，否则现截。这也绕开了视频分段写入期间读不到最新截图的限制。
- `RecentContext`：最近约 5 分钟、最多 5 个状态。应用切换或画面明显变化（dHash）时新增，同一应用内的小变化只更新最后一个。只保存压缩后的画面；OCR 在有人读取时才做并缓存，不使用任何语言模型。
- 交互式读取经过同一个隐私策略：被排除的应用在前台或正在输入密码时拒绝。用户暂停后台采集时，交互式读取仍可用（它是用户当下主动发起的），但最近状态停止积累并清空。
- Amai 自己的窗口从所有截图中抠掉（包括后台采集），避免把聊天面板录进记忆。

### 快速文本操作与替换

> 2026-11-18：快速操作面板与 ⌥⇧Space 已移除（用户决定）。翻译、润色、解释、概括并入聊天面板：打开面板前有选区时作为建议出现，作为普通一轮对话发送；回答下方提供复制与重新生成（重新生成会撤回最后一条回答、把会话退回到那个问题之前再问一次）。翻译、润色两项不检索记忆（只处理选中的文字，检索只会带来无关来源）。替换原文随之删除：感知层的写回、粘贴与可写性判断都已移除，复制回退只剩菜单"拷贝"、不再发送 ⌘C。以下为原始决策记录。

- 一次性的文字进、文字出：不带历史、不带工具、不读记忆、不经过 Agent 循环；与 Agent 共用同一个模型。
- 选区在面板出现之前读取；替换只在用户点击时进行：先经辅助功能直接写入（确认控件里选中的仍是原文），控件不支持时改为粘贴（之后恢复剪贴板），仍不行则只复制。输入密码时不读取也不发送按键。
- 2026-11-18 更新（参考 AtD 的 Selection 模块，见 `docs/references/atd.md`）：
  - 读取改为多级（`AXSelectedText`、Web Text Marker、`AXSelectedTextRange` + `AXStringForRange`、`AXValue` 截取），并搜索焦点的子控件与父控件。
  - 辅助功能看不出选区时，**只在快速操作快捷键**这一次读取里经"复制"补读：优先菜单栏"拷贝"，必要时 ⌘C；剪贴板完整快照并恢复。聊天面板的读取（含定期刷新）仍只用辅助功能，不发按键。
  - 焦点是空的原生文本框、但菜单"拷贝"可用时（微信：在消息气泡里选字，键盘焦点仍在输入框），快捷键读取只经菜单复制一次、不发 ⌘C，结果不可替换。聊天快捷键打开面板之前也读一次：辅助功能读不到时只经可用的"拷贝"菜单复制（不发 ⌘C），读到的选区交给聊天框保留到下一次提问；面板打开后的刷新仍只用辅助功能。
  - 替换前核对前台应用、焦点控件和选区都没变；只有原生文本控件经辅助功能直接写入，网页 / 自绘编辑器改为粘贴（走应用自己的编辑模型）；有只读证据（网页正文、PDF）时不写也不粘贴，只复制。
  - Electron 应用（VS Code、Cursor、Slack 等）不再设置 `AXManualAccessibility`，改为读一次应用的 `AXRole` 唤醒基本辅助模式：前者会让 VS Code / Cursor 以为有屏幕阅读器并切换编辑器模式。Chromium 浏览器仍设置 `AXManualAccessibility`。

### 权限与云端边界

- `config.json` 的 `assistant` 段：Agent 模型（无默认值）、辅助视觉模型（可选）、可读的记忆分区、快捷键、云端确认标记。
- 可读分区对本地与云端模型是同一份授权（`MemoryAccess`），默认综合、工作、目标与每日记录；健康与财务需要用户勾选。
- 选用云端模型时确认一次发送范围；之后的调用不再询问。发送范围（服务或可读分区）变化时重新确认。聊天面板与快速操作面板标出当前是本地还是云端模型。
- 新增一项可选权限：辅助功能（读窗口标题与选区、写回选区）。没有它时对话仍可用。

## 备选方案

- **让快速操作也走 Agent 循环**：多一轮上下文收集与工具定义，延迟更高，还会顶掉对话的 KV cache。未采用。
- **每轮都附带截图**（Eira 的做法）：对云端模型既费 token 又扩大了发送范围；改为文字上下文默认带、截图按需。
- **OCR 留在抽取层，交互式读取另写一份**：两份实现。改为契约在 AmaiCore、实现在感知层。
- **助手单独一套云端账户设置**：重复界面与钥匙串条目。改为沿用记忆整理的账户，只选来源与模型名。
- **引入 SwiftMath 排版公式**（Eira 有）：需要一个 fork 依赖。暂不引入，公式显示 LaTeX 原文。

## 取舍与风险

- 小的本地模型（Gemma 4 E4B）调用工具不稳定：实测会把"某天做了什么"当成检索来问。已做两点缓解——提示词明确要求先调用工具；查询本身是日期时检索工具直接返回当天时间线。追问时仍可能答非所问，属于模型能力限制。
- 对话的 KV cache 在抽取峰值内存之上再占一部分；内存压力时随模型一起释放。
- 2026-11-18：助手的本地对话模型改为常驻（参考 Eira）：启动时后台预加载，不做空闲卸载，只在 critical 内存压力（且两分钟内没有对话）时释放；向量模型随之常驻。代价是常驻内存（26B 约 18 GB），换来按下快捷键后不再有 5–15 秒的冷加载。后台抽取模型仍空闲 5 分钟卸载。
- 粘贴替换无法确认原应用是否接受，界面上如实说明。
- Chromium 浏览器的选区依赖 `AXManualAccessibility`（会让浏览器进入完整辅助模式，有一定性能开销）；Electron 应用只唤醒基本模式，读不到时靠复制回退。
- 复制回退的已知副作用：剪贴板管理器可能记录被复制的文字；VS Code 在没有选区时会复制当前整行（`editor.emptySelectionClipboard`），会被当作选区。
- 表格（Numbers、Excel 等单元格选区）未特殊处理，可能只读到当前单元格或读不到。
- 云端对话没有自动重试（重试会让已显示的文字重复），失败由用户重发。

## 影响

- 新增 target：`AmaiInference`、`AmaiAssistant`；`AmaiCloud` 改为依赖 `AmaiCore`。
- 后台采集的画面不再包含 Amai 自己的窗口。
- 新增数据：对话记录 `index/assistant.sqlite`（提问、回答、引用的来源；不含截图与屏幕文字），用户可删除，不属于记忆。
- 文档：`architecture.md`、`product.md`、`roadmap.md`、`release.md` 同步更新。
