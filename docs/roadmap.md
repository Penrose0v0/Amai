### M1 · 感知骨架（屏幕 + 键鼠 + 控制）

目标：能开着不烦人的采集器。

- 菜单栏应用：运行 / 暂停 / 停止，状态图标，权限引导。
- ScreenCapture：ScreenCaptureKit 单帧定时截图（默认 10 秒），dHash 去重，前台应用 / 窗口元数据，每帧附空闲秒数；睡眠 / 锁屏暂停；失败退避。
- InteractionCapture：空闲时长 + 焦点切换，安全输入检测，无按键内容。
- RawSpool：容量 / TTL 双上限，重启恢复。
- PrivacyPolicy：排除应用 / 窗口列表、暂停、安全输入跳过，fail-closed。
- PowerProfile：电池 / 插电 / 热状态三档节流。
- Logging：无内容字段。

实现进度（2026-10-19）：
- [x] 菜单栏：开始 / 暂停 / 继续 / 停止，四种状态图标，权限申请与系统设置入口，计数显示。
- [x] ScreenCapturer：SCK 单帧定时截图，dHash 标记重复帧，空闲秒数与前台应用元数据，失败退避 60/120/300/600 秒，权限拒绝标记。
- [x] FrameStore（2026-10-20，按用户要求改为 Dayflow 的视频分段方案）：所有帧追加进 HEVC/MP4 分段，600 帧 / 600 秒 / 尺寸变化轮换，`.part` → `.mp4`，睡眠 / 锁屏 / 暂停 / 停止时结束分段；按帧号读回。
- [x] InteractionMonitor：焦点切换事件；被排除应用只留占位。
- [x] RawSpool：按日目录 + JSONL 索引，TTL 整日清理，容量按最旧 payload 清理（跳过写入中的 `.part`），重启重新计量。
- [x] PrivacyPolicy：排除 bundle id / 应用名、用户暂停、安全输入；SCK 过滤不完整时拒绝截图（fail-closed）。
- [x] PowerProfile / PowerMonitor：IOKit 电池 + 热状态 + 低电量模式，四档。
- [x] SystemStateMonitor：睡眠 / 锁屏 / 屏保暂停，恢复延迟 5 秒。
- [x] 单元测试 41 个：spool 限额与恢复、哈希、电源规则、tick 的捕获 / 去重 / 跳过 / 阻断 / 退避路径、焦点事件排除。
- [ ] 窗口标题元数据（SCK 截图路径未取窗口标题，M2 视需要补）。
- [ ] 活动强度统计（CGEventTap，需输入监控权限）。

验收：
- [ ] 连续运行 8 小时无崩溃；CPU / 内存在 product.md 目标范围内（记录测量数据）。
- [ ] 权限撤销 / 恢复、显示器插拔后自动恢复（Recovery Test）。
- [x] spool 不超过上限，过期数据被删除（单元测试）。
- [x] 密码框输入期间无采集记录（单元测试：安全输入 → 占位事件，不调用截图）。
- [x] 启动冒烟：应用启动、生成默认配置与目录、干净退出。
- [x] 真机截图验收（2026-10-20 凌晨，作者机器 M5 Pro）：权限授权后正常落盘；索引与文件一致（38 个截图事件 = 22 重复占位 + 16 个 JPEG）；焦点切换事件正常。
- [x] 视频分段真机验收（2026-10-20 中午）：帧按序写入 `.mp4.part`，重复帧标记正确；授权对话框输入密码期间出现 `secureInput` 占位，证明安全输入检测在真机生效。
- [x] 稳定签名：`scripts/setup-dev-cert.sh` 创建 `Amai Local Dev` 证书后，屏幕录制授权跨重新打包保留（此前 ad-hoc 签名导致每次打包后权限失效，表现为"已授权但仍缺权限"）。
- [x] 菜单栏简化为开始 / 暂停 / 继续；退出时先收尾分段。

首次实测（运行约 9 分钟，10 秒间隔，1080p，JPEG 0.75，接电 performance 档）：

| 指标 | 实测 |
|---|---|
| CPU | 0.1%（采样时） |
| 常驻内存 RSS | 约 105 MB |
| dHash 去重率 | 约 58% 的 tick 判定为同屏，不落盘 |
| 单帧 JPEG | 160–300 KB |
| 磁盘增长 | 约 30 MB / 小时（推算），72 小时 TTL 对应约 2.1 GB，与默认 2 GB 容量上限相当 |

HEVC 分段实测（2026-10-20 中午，同参数，质量 0.55，1662×1080）：

| 指标 | 实测 |
|---|---|
| 第一个分段 | 59 帧 / 10 分钟，1.75 MB |
| 磁盘增长 | 约 10.5 MB / 小时（与 Dayflow 的 10.3 MB / 小时一致），72 小时约 760 MB，远低于 2 GB 容量上限 |
| 索引一致性 | events.jsonl 中引用该分段的帧数 = 容器实际帧数 = 59 |
| 常驻内存 RSS | 约 127 MB |

结论：改为视频分段后磁盘增速约为逐帧 JPEG 的 1/3，TTL 会先于容量上限触发清理；资源占用在 product.md 目标内。

### M2 · 屏幕抽取与活动片段

目标：从截图得到"刚才那 15 分钟在干什么"。

范围（2026-10-20 用户确认）：以 MVP 为目标，优先保证端到端稳定、记录准确、结果可检索；不做模型微调、复杂意图识别或专门的视频理解模型。连续活动理解后续单独研究（参考 Audio Description 领域）。

实现进度（2026-10-20）：
- [x] 帧筛选：dHash 去重 + 应用切换优先 + 均匀采样；有键鼠输入的相似帧不丢弃。
- [x] 观察抽取：每帧一条事实（元数据 + Vision OCR，凭据脱敏）与一条推断（VLM 描述），带证据引用。
- [x] 活动切分：一个窗口可多个片段，可跨窗口延续；输出校验、重试与兜底。
- [x] 空闲判定：键鼠空闲且画面不变才判离开；隐私跳过时段单独成段。（多屏后改为：键鼠空闲且**焦点屏**画面不变；副屏变化只作为独立信息记录。）
- [x] MLXModelProvider：Gemma 4 e4b 嵌入式，按需加载、空闲 5 分钟卸载、内存压力卸载，不自动下载。
- [x] 增量处理：水位线、帧未写完时等待、电源节流。
- [x] 最小检查器：按天列出片段、关联观察（事实 / 推断标注）、关键帧缩略图与放大、7 天文字检索（含 OCR 文本）、删除。
- [x] 测试 81 个，含用假模型 / OCR / 数据源的端到端流水线测试。

验收：
- [x] 合成数据的 Pipeline Test：固定事件序列 → 稳定的片段输出（假模型）。
- [x] 本地模型不可用时流水线暂停 / 恢复而不丢数据（单元测试）。
- [x] 真机端到端（2026-10-20，Gemma 4 e4b，M5 Pro）：约 45 分钟积压在约 2 分钟内处理完（含模型加载）；推理期间 RSS 约 4.7 GB、CPU 约 94%，空闲 5 分钟后卸载。
  - 首轮发现 e4b 切分过碎（30 分钟 18 个片段，多为 20 秒到 2 分钟），且把"画面不可用"标注写成标题。修正：提示词约束片段时长与标注含义，并加确定性后处理把短于 3 分钟的片段并入相邻片段。修正后同一时段为 6 个片段、每个 6–15 分钟。
- [ ] 作者实际使用 3 天，片段"基本准确"（主观评估记录在 roadmap）。

### M3 · Markdown 记忆写入与检索

目标：daily 自动生成，记忆可检索。

决定（2026-10-20 用户确认）：记忆目录 `~/.amai/memory/`（可配置）；daily 使用 HTML 注释管理的系统区块，区块外由用户自由编辑，每个片段保留稳定 ID；正常与低置信度片段写入（后者加标记），空闲与隐私跳过不写入。

实现进度（2026-10-20）：
- [x] MemoryStore：daily 时间线区块渲染与拼接，写前重读、内容不变不写、原子写入，区块损坏时拒绝写入。
- [x] MemoryIndex：SQLite FTS5 trigram 分词（中文可检索句中词），短查询子串匹配，范围与日期过滤，按修改时间增量刷新，可全量重建。
- [x] MemorySync：以片段 `updatedAt` 为水位线增量同步，水位线持久化，重启不重复写入。
- [x] Retrieval：内部接口 + 检查器"记忆"检索模式 + 开发用命令行 `amai-memory`。
- [x] 删除：检查器"删除时间段"同时清理 raw / extracted / daily 区块；单个片段删除立即重渲染。
- [x] 测试 96 个。
- [ ] 文件变化事件监听（MVP 用 60 秒轮询）。

验收：
- [x] 从 ActivitySegment 到 daily 文件的 Pipeline Test（MemorySync 测试，假片段源）。
- [x] 用户手动编辑 daily 后，系统不覆盖区块外内容（单元测试）。
- [x] 删除某时间段后，daily / extracted / raw 中相应数据全部消失（各层单元测试；真机未做）。
- [x] `rebuild()` 可从零重建索引且检索结果一致（单元测试）。
- [x] 真机：`~/.amai/memory/daily/2026-10-20.md` 由真实片段生成，命令行检索中文命中。

- [x] App：`consolidationModel` 配置、设置窗口（模式、提供商、模型、推理强度、Key、测试连接）、开启云端前确认、菜单显示当前整理模型。

### M4.2 · 用 ChatGPT / Claude 订阅额度做记忆整理

设计见 ADR-0005（Accepted）。整理模型来源扩展为本地、API Key、ChatGPT 订阅、Claude 订阅四种，默认本地。

实现进度（2026-10-22）：

- [x] 测试 141 个：SIWC 完整登录流程（真实本机回调 + 桩授权服务 + 测试 RSA 签名的 ID token）、state 校验、刷新串行与轮换、终止性刷新错误、撤销、模型列表、流式解析、Schema 退路、额度与 401 处理；Claude Code 参数、环境、输出解析、错误分类、状态、路径查找。
- [x] 真机：Claude Code 订阅（Max）在 App 进程中完成 summary 更新，改动日志记录 `claude-code:opus`。
- [x] 真机：ChatGPT 订阅（用户在浏览器中完成授权）。`gpt-6.1-sol` 完成日终摘要（1196 输入 / 250 输出 token，9 秒）与 work 专题判断（无更新）；SIWC 路由支持 JSON Schema 结构化输出。

顺带修复（M1/M2 遗留缺陷，2026-10-22 端到端测试中发现）：
- 进程被强制结束或崩溃时，写入中的视频分段（`.part`）残留，读取方永远视其为"仍在写入"，抽取从 10-20 起停住。修复：分段改为分片写入（与关键帧对齐，每 30 帧一片），启动时先恢复残留分段（可读的转正，不可读的标记为 `.broken` 交给保留策略清理）再开始采集；读取方把超过 15 分钟未更新的 `.part` 视为过期。

此前估算的 15–25 MB/小时是两屏合计（每屏每小时 360 帧 × 20–30 KB），按画面持续变化的情况估计，属于上限。日常使用下重复帧多，实测约为估算的一半以下；按实测速率 72 小时约 0.6 GB，低于 2 GB 上限。副屏长时间播放视频时会接近估算上限。
